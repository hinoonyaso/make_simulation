# V11 architecture

V11 adds an import-light capability catalog, a small `MechanismAdapter` Protocol, lazy adapter loading, and one production CLI. Existing trace schemas remain in domain payloads; `mechanism-envelope/v1` adds execution provenance and limitations around new numerical adapters. RAG delegates to V10, while the H1 adapter delegates to the existing MuJoCo runner. V9 manifest generation and Manim delivery validation are reused.

V11.3 flow: Korean/English topic alias → unique capability lookup → executable adapter or validated replay input → domain validator → content-addressed run directory → trace-driven storyboard with explicit phase IDs → trace-backed visual plan → V9-compatible manifest → topic-capable renderer backend (Manim, H1 Blender trace playback, or YOLO image-space Manim) → metadata/hash/full-decode validation → separate visual/educational review status. Known `mechanism-envelope/v1` traces are validated by both envelope and topic-specific adapter logic. RAG and V9 H1 replay use their pre-existing trace schema and model/family identity. YOLO uses its own execution-trace schema and validates the embedded input-image hash. Ambiguous aliases return candidate canonical IDs and are not auto-routed.

Adapters are loaded only after lookup so catalog inspection does not require MuJoCo, Manim, or model runtimes. Domain traces are not converted into one shared payload schema. Quantization uses affine ranges including real zero; NMS and PID validators independently recompute recorded decisions/state; Self-Attention records each matrix stage. Asset resolution stays local and converter injection remains explicit. The environment registry and loader preflight are separate from actual backend loading; no candidate is marked ready without load/physics/render evidence.

Run identity partitions topic/input/config/trace/renderer settings and render-relevant source fingerprint. A completed matching run is reused only when the expected in-run output path, media hash, codec, resolution, frame rate, duration and full decode still match the report; an incomplete or colliding run is preserved. Dynamic storyboard timing is an estimate unless a measured narration duration is passed. This remains a silent technical-render path: narration, caption rendering, Reviewer execution, and final V9 delivery are not orchestrated by the V11 CLI. The pinned HTTPS archive helper is bounded and opt-in by metadata, but current environment candidates lack verified hashes/revisions and dependencies. See [environment validation](environments/ENVIRONMENT_VALIDATION.md), [capability matrix](CAPABILITY_MATRIX.md), and [limitations](LIMITATIONS.md).

V11.4 inserts visual-goal routing and process preflight before run identity, then writes one `mechanism-timeline/v1` artifact for Manim, YOLO, H1 Blender and the retained four-stage RAG path. The timeline uses contiguous integer frames and optional source-time mappings. Run identity includes requested/effective renderer, goal, timeline digest, renderer version and local model bundle hash. Details are in [routing](V11_4_RENDERER_ROUTING.md) and [timeline contract](V11_4_TIMELINE_CONTRACT.md).

## V11.5 accuracy and execution boundary

Heavy YOLO/H1 adapters now pass through `execution_cache.py` before execution. Content-based requests, Linux process reservations, atomic completed records and domain validation produce a trace independently of render choices. The existing renderer/run boundary remains intact. `joint_motion.py` provides full-trajectory routing evidence; `pid_playback.py` supplies discrete frame state; the timeline supplies per-phase speed metadata to H1 export and Blender. Design choices and caveats: [execution cache](V11_5_EXECUTION_CACHE.md), [motion and playback](V11_5_MOTION_VALIDATION.md).
