# Deep-read pass

Use for one-paper reading, verification or comparison.

1. Identity: exact revision + code/checkpoint commit/version if used.
2. Data flow: input -> preprocessing -> representation -> core operation -> decode/action. Record relevant shapes/frames/units/rates.
3. Equations: define notation, separate training losses from inference updates, and connect terms to computation.
4. Evidence: experimental setup, dataset/task/embodiment, baselines, metrics, seeds/statistics if reported, and limitations/failures.
5. Claim ledger: `claim | exact source location | evidence type | limitation`.
6. Comparison: only directly compare compatible protocols; otherwise report contextual differences.

If implementation details are missing, mark them unknown instead of completing the method from intuition. If a figure carries key information, inspect the PDF figure itself.
