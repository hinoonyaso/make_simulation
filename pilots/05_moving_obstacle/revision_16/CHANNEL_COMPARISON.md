## 높은 우선순위 — 설명 관계를 강화

### 1. 새 기호를 말로 안내하고, 반지름 차이를 그림에서 직접 뺀다
- 참고: [선형변환과 행렬](https://www.youtube.com/watch?v=35ESC-g49fY),270–310/360–400초. 동일 벡터의 계수·좌표가 그림과 식에 대응한다. [공식 설명](https://www.3blue1brown.com/lessons/linear-transformations/)에서도 기준 벡터의 이동→선형결합→행렬 표기로 이어진다.
- R16: B14,206.77–233.23초. rL/rR/θ를 식의 항으로 복사하는 개선은 확인했다. 그러나 음성에는 반지름·공통각·호의 길이 설명이 없고, 화면 상단의 `rR−rL=b`는 처음부터 완성된 등식이다. 같은 각도라는 사실과 `s=rθ`를 처음 보는 사람은 직접 보충해야 한다. 사용자 피드백은 속도가 따라가기 좋다는 근거이며 새 기호의 이해까지 증명하지 않는다.
- 보완: 같은 θ가 두 호에 적용됨을 표시→긴 반지름에서 공통 짧은 반지름을 겹쳐 제거→남은 구간을 기존 b 표시와 연결. 기존 설명 문장을 “두 바퀴는 같은 각도만큼 돕니다. 이동 거리는 반지름×각도입니다. 두 반지름의 차이가 바퀴 간격입니다”처럼 실제 등장 관계를 안내하는 문장으로 교체하는 안을 검토한다. 현재 읽기 시간을 유지하고 식을 더 추가하지 않는다.
- 확인: 새 voiced excerpt에서 그림/단어/항이 같은 순서인지 검사; 첫 시청자에게 왜 반지름 차이가 바퀴 간격인지 질문. 예상 효과는 아직 미검증.

### 2. 실제 기록에 이미 있는 오른쪽 보정 명령을 발견의 결말로 강조한다
- 참고: [CPU](https://www.youtube.com/watch?v=Fg00LN30Ezg),900–960초의 활성 데이터·레지스터 변화; [경사하강법](https://www.youtube.com/watch?v=8861RzFOFs8),360–420초의 위치/기울기/이동 방향 관계.
- R16: B19,300–315.10초. 상태와 명령을 같은 실행에서 갱신하는 개선은 확인했다. 308–310초에 방향 차이가+0.31→−0.07rad로 바뀌고 좌우 목표의 크기 관계가 뒤집히지만, 동일한 작은 숫자 줄과 “명령이 달라집니다” 문장으로 지나간다.
- source 근거: R06 command sample120(4초),오차−0.071523rad,ω목표−0.157351rad/s,왼쪽0.222147/오른쪽0.176830m/s. 현재 왼쪽이 더 빠른 것은 기록과 일치한다.
- 보완: 오차0 통과→현재/목표 방향의 순서 반전→왼쪽 목표가 더 커짐을 하나씩 강조. “이제 목표 방향이 반대쪽이므로 오른쪽 보정 회전 명령을 냅니다”를 해당 상태에 연결. 명령의 반전을 실제 몸이 즉시 오른쪽으로 돈다는 주장으로 바꾸지 않는다.
- 확인: 같은 기록의 sample 전후 값/방향·부호 유지; 시청자가 어느 바퀴 목표가 더 크고 왜인지 답할 수 있는지 확인.

### 3. 2D→3D 전환을 같은 상태에서 연결한다
- 참고: [모터](https://www.youtube.com/watch?v=OcYdo3-Tx_o),534초 부근의 같은 R/S/T 위치·색을 유지한 입체 코일/단면 대응. [드론](https://www.youtube.com/watch?v=d7RfB4Gf02Y),94초 부근의 실제 모터/프로펠러 연결.
- R16: B19 끝은 실험4초. B20 시작315.10초부터 “실험2→30초”를 다시 재생한다. 314.8→315.3초에서 로봇 중심의 local2D 화면이 드럼 중심의3D 전체 화면으로 바뀌고, 드럼은 이전2D view에 없다. 같은 데이터라는 표기는 있으나 같은 위치/방향을 화면만으로 즉시 대응시키기 어렵다. 재생 구간을 표시했으므로 허위 데이터 문제로 판정하지 않는다.
- 보완: 같은 source4초 pose/앞쪽 목표/경로 구간을 양쪽 뷰에 잠깐 유지하고, 드럼이나 경로의 꺾임을 고정 기준점으로 삼아3D로 이어간다. 이후4→30초로 계속하거나,2초부터 다시 보는 이유를 분명히 설명한다. 단순 dissolve만으로 대응을 해결했다고 판단하지 않는다.
- 확인: 최종 컷 전후 source time/pose/색/화면 기준점 비교. 검증된 기존 trace 재사용으로 가능하나 기존 encoded media의 source time 대응을 확인해야 한다.

## 중간 우선순위 — bRd의 물리 근접 설명과 표면 읽기

### 4. 바퀴쌍 전체 뷰 뒤에 접점 하나를 설명하는 컷
- 참고: [기차](https://www.youtube.com/watch?v=eW5JF-AA-uY),57.5초의 두 회전 반경 표시→77.5–82.5초의 플랜지/레일 접점. 넓은 시스템과 결정적 접점이 서로 다른 역할을 한다.
- R16:112.90–130.40초. 기록된 바퀴 회전·차축 중심·방향·지면 history는 잘 연결됐다. 그러나 높은 시점은 두 바퀴 전체의 이동 비교에 맞춰져 있어 접촉부의 굴림을 세밀하게 읽는 데는 한계가 있다.
- 보완: 현재 두 바퀴 전체 뷰는 유지하고, 바퀴 한 개의 회전 표식과 바닥 기준점이 함께 보이는 낮은 근접 컷을 짧게 추가/교체한다. 바퀴 표면점과 중심 이동의 관계를 설명한다. 이것은 굴림/접촉 설명 깊이를 추가하는 선택이며 기존 방향 차이 설명의 실패가 아니다.
- 데이터 경계: source quaternion/root pose로 회전·중심 이동을 표현할 수 있다. 정확한 접촉점·미끄럼·힘은 별도 trace에 있는지 확인해야 한다. 현재 없는 접촉력을 정량 화살표로 발명하지 않는다. 순수 굴림 기하를 쓰면 이상적 도식임을 명시한다.

### 5. 재질 이름보다 필요한 부품 경계의 분리를 다듬는다
- 참고: 기차 바퀴/레일의 반사 띠와 단면,모터 코일/몸체의 표면 차이. 금속 광택이나 어두운 배경 자체를 필수 스타일로 취급하지 않는다.
- R16:121.6/130.3초,바퀴 구분은 읽히지만 몸체 상판과 바닥은 여전히 유사한 밝은 회색이며 상판층의 깊이 구분 개선은 작다.
- 보완: 같은 pose/camera에서 상판/측면 경계와 접촉 그림자가 보존되는 조명·roughness 조합2–3개만 비교. 현재 밝은 스튜디오를 유지한다. 배경 전체를 어둡게 하거나 faithful 형상을 임의로 변경하는 것을 해결 기준으로 쓰지 않는다.
- 확인: native1080p의 층/타이어/바닥 접촉 구분,움직이는 highlight/flicker는 실제 재생으로 별도 확인.

## 구성과 길이 — 확대보다 연결 우선
시작0–64.47초에 경로/앞쪽 지점 문제를 설정한 뒤64.47–250.83초에 바퀴 실험·기하를 다루고,250.83초에 실제 제어 명령으로 돌아온다. 구조는 타당하지만 처음 문제의 “이 왼쪽 목표를 어떻게 실행할까” 연결이 긴 원리 구간에서 약해질 가능성이 있다. 이는 초보자 이해 저하를 측정한 결과가 아니라 구성상 개선 가설이다. 제어 단계로 돌아갈 때 처음의 같은 목표/pose를 재사용하고, 필요한 중간 지점에 짧게 문제를 회수하는 방향을 추천한다. 세 실험을 무조건 삭제하거나 영상 길이를 두 채널에 맞춰 늘릴 근거는 없다.5분56초는 현재 범위에 적절하며 추가 컷은 중복 설명을 대체하는 방식부터 검토한다.

## 권장 순서와 보존할 성과
1→2→3은 기존 기록 안에서 설명의 연결을 강화한다.4는 물리 메커니즘 설명 범위를 넓히는 선택이고5는 표면 개선이다. 이미 성공한 바퀴 확대/기록 대응,간격2배의 그림 비교,승인된 도출 속도,데이터 경계는 유지한다. 새로운 스킬 지침이나 기술PASS만으로 개선 효과/채널 동급을 선언하지 않는다.

아까 “핵심 장면이 견줄 만하다”는 표현은 넓었다. 이번 재대조에서 더 정확한 결론은 “그림→식·부품 연결의 주요 기법을 구현했으며,말의 안내·결정 순간 강조·표현 간 상태 연결에 구체적인 격차가 남아 있다”다. 채널 전체와 동급이라는 판정은 이 검사 범위에서 하지 않는다.
